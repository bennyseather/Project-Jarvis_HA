# Purpose

Define the safe runtime entry point that accepts a user request and routes it through the composed read-only Jarvis assistant slice.

# Decision

M5.3 introduces one explicit application method, `handle_request(text)`, which delegates to the M5.1/M5.2 read-only assistant composition. It replaces demonstration conversation calls during startup; startup performs connectivity only and never executes a Home Assistant action.

The entry point receives plain user text and returns the structured assistant result. It uses configured allow-listed entities only. It does not add a UI, voice loop, HTTP server, streaming, state-changing command, automation, or background task.

# Acceptance Criteria

- Application startup performs no Home Assistant service call or demonstration conversation.
- A caller can submit one request through `handle_request`.
- Conversation and one allow-listed read-only entity query work through injected adapters.
- Unsupported proposals, unavailable entities, and provider failures return structured outcomes.
- Tests use injected fakes and verify no disallowed Home Assistant call occurs.

# Approval Decisions Required

1. Approve `handle_request(text)` as the first runtime entry point.
2. Approve no UI/server/voice loop in this milestone.
3. Approve startup remaining connectivity-only and free of demonstration requests.
