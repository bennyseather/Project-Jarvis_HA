# Purpose

Define the privacy, consent, and ownership boundaries for future Jarvis learning without implementing automatic learning or collecting new durable data.

# Decision

Learning is optional and subordinate to Memory, Knowledge, Home Assistant, and explicit user control. Jarvis may not infer durable preferences, facts, routines, security posture, or automation behavior from conversations, actions, events, or Home Assistant state in the initial release.

Future learning proposals must be explicit, inspectable, correctable, and deletable. Any durable item created from a learning proposal must use the existing Memory or Knowledge policy-controlled writing path; Learning owns neither a parallel datastore nor Home Assistant state.

## Prohibited Initial Behavior

- Automatic preference or routine inference.
- Silent persistence of conversation, event, or action observations.
- Training-data export, external analytics, profiling, or user scoring.
- Autonomous changes to Home Assistant configuration, services, or automations.
- Learning from sensitive, security, lock, alarm, presence, health, or credential data.

## Future Proposal Requirements

A future learning capability must provide a human-readable proposal, source category, confidence explanation, exact durable destination, and explicit approval/correction/deletion controls. Missing consent or unclear provenance is a rejection.

# Acceptance Criteria

- No current component performs automatic learning or inferred persistence.
- Memory and Knowledge remain the only durable destinations.
- Future learning design must be explicit, reviewable, correctable, and deletable.
- Home Assistant remains the state and automation owner.

# Status

Approved policy foundation only; no learning engine or storage is implemented.
