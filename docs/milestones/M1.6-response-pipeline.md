# Purpose

Normalize an execution outcome into a structured, provider-neutral Response for future presentation layers.

# Background

The response pipeline completes EPIC 1 by transforming the result of Jarvis orchestration into a structured Response. It receives the shared RequestContext and adds the response without generating natural language, constructing prompts, or contacting external systems. Presentation layers may later render the same Response for an LLM, template, voice interface, or mobile application.

# Functional Requirements

- Receive a RequestContext containing an ExecutionResult.
- Normalize execution status, message, metadata, error information, and follow-up state into a Response.
- Add the Response to RequestContext.
- Preserve the terminal RequestContext lifecycle state after response normalization.
- Support an injected ResponseRenderer protocol.
- Provide a StructuredResponseRenderer that returns the Response unchanged.
- Produce deterministic output for an injected timestamp source.

# Deliverables

- A Response model and response-status contract.
- A ResponsePipeline and ResponseRenderer protocol.
- A StructuredResponseRenderer.
- Tests for successful, unavailable, cancelled, and rendered responses.

# Acceptance Criteria

- Every execution outcome produces a Response path.
- Response status and metadata accurately reflect the structured execution outcome.
- Unavailable, cancelled, and unsuccessful outcomes are distinguishable from success.
- The pipeline does not independently execute capabilities, generate language, or alter Home Assistant state.
- Tests demonstrate deterministic normalization and rendering.

# Out of Scope

- Request classification.
- Capability discovery or execution.
- Context assembly beyond consuming the supplied context package.
- LLM prompt or natural-language generation.
- Voice or Markdown formatting.
- Home Assistant or memory integration.

# Dependencies

- M1.1 Request Classification.
- M1.2 Capability Registry.
- M1.3 Request Context.
- M1.4 Context Assembly.
- M1.5 Execution Pipeline.
