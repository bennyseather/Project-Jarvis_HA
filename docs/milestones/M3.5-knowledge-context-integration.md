# Purpose

Integrate policy-eligible, bounded Knowledge retrieval into Context Assembly without exposing concrete storage, ranking internals, or Home Assistant state.

# Background

M3.4 supplies deterministic Knowledge retrieval. Context Assembly already supports Memory through a typed provider-neutral contract. M3.5 applies the same bounded-provider pattern to curated Knowledge while preserving the separation between Knowledge, Memory, Home Assistant, and language-model reasoning.

# Proposed Architecture

## Typed Context Shape

Replace `ContextPackage.knowledge: Mapping[str, object] | None` with `KnowledgeContext | None`.

```python
@dataclass(frozen=True, slots=True)
class KnowledgeContextMatch:
    content: str
    title: str | None
    knowledge_type: KnowledgeType
    tags: tuple[str, ...]
    source: KnowledgeSource
    retrieval_score: float


@dataclass(frozen=True, slots=True)
class KnowledgeContext:
    matches: tuple[KnowledgeContextMatch, ...]
    result_limit: int
```

Included fields are the approved, curated information useful to later reasoning. The context excludes `knowledge_id`, request correlation, timestamps, status, internal metadata, score breakdowns, and match diagnostics. Those fields are not needed for contextual reasoning and must not be leaked through the default context path.

`None` means no Knowledge provider is configured. A configured provider with no eligible match returns `KnowledgeContext(matches=(), result_limit=...)`.

## Provider Boundary

Add `KnowledgeContextProvider`, implementing the existing `ContextProvider` protocol. It depends only on `KnowledgeRetriever`, constructs a `KnowledgeRetrievalQuery` using the original request text and an approved bound, and converts returned matches to the typed context model.

It must not import or access `KnowledgeStore`, `KnowledgeRanker`, `PolicyControlledKnowledgeRetriever`, a document parser, Home Assistant, or an LLM. It must not rerank, filter, write, parse, or infer Knowledge.

## Bounded Results and Failure Behavior

The default Context Assembly limit is five matches and the hard maximum is ten. The provider supplies that limit to retrieval and defensively slices an overfull provider result while preserving order.

No result or policy-excluded records are normal outcomes and produce an empty typed Knowledge context. A retriever failure is an infrastructure failure: under the existing ContextAssembler contract, it propagates, marks the request `FAILED`, and prevents a partial package being treated as successfully assembled. Optional-provider degradation is a future resilience decision.

# Functional Requirements

- Define `KnowledgeContext` and `KnowledgeContextMatch` in the context-model layer.
- Change `ContextPackage.knowledge` to use `KnowledgeContext | None`.
- Implement `KnowledgeContextProvider` through `KnowledgeRetriever` only.
- Use original request text and a five-result default with a maximum of ten.
- Expose only the approved safe context fields.
- Preserve retriever ordering and enforce the result bound defensively.
- Produce empty typed context for normal empty retrieval results.
- Preserve existing ContextAssembler failure behavior for retriever failures.

# Acceptance Criteria

- Context Assembly receives Knowledge without concrete backend or ranking dependencies.
- Populated Knowledge context contains only approved typed fields.
- Empty, bounded, deterministic, and retriever-failure outcomes are tested.
- M3.5 adds no writing, correction, deletion, parsing, importing, Home Assistant call, LLM call, embedding, semantic search, or automatic Knowledge creation.

# Out of Scope

- Knowledge management, inspection, deletion, document import, and persistent storage.
- Memory Context changes, prompt construction, LLM interaction, Home Assistant integration, and optional-provider resilience.

# Dependencies

- M1.4 Context Assembly.
- M3.1 Knowledge Contracts and Boundaries.
- M3.4 Knowledge Retrieval.
- ADR-001 Project Scope.

# Approval Decisions Required

1. Approve the typed `KnowledgeContext` contract and safe field list.
2. Approve the default limit of five and hard maximum of ten.
3. Approve `KnowledgeContextProvider` depending only on `KnowledgeRetriever`.
4. Approve empty typed context for no results and request failure for retriever infrastructure errors.
