# M7.6 Operational Readiness

## Startup diagnostics

At startup, Jarvis reports only aggregate operational information: discovered
entity count, allowed read count, and allowed action-entity count. It does not
print the full entity inventory, credentials, confirmation tokens, or provider
payloads.

If Home Assistant connectivity or startup checks fail, Jarvis reports a clear
unavailable status and exits cleanly without attempting an action.

## Operator runbook

1. Keep Home Assistant credentials in `config/secrets.yaml`, not in source
   control or console output.
2. Start Jarvis only after reviewing `allowed_read_entities`,
   `allowed_entities`, and confirmation-required services in
   `config/general.yaml`.
3. Treat the console confirmation token as one-time and short-lived. Reissue
   the request rather than retrying an expired or rejected token.
4. If startup reports Home Assistant unavailable, verify Home Assistant is
   running and the configured URL and credentials are correct; then restart
   Jarvis.
5. Keep `conversation.max_messages` small. Conversation context is in-process
   only and is discarded on restart.
