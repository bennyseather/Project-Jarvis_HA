# Purpose

Implement a deterministic, provider-neutral in-memory reference backend for the approved Jarvis memory contracts.

# Background

M2.1 and ADR-003 define the memory taxonomy, privacy policy, lifecycle, and provider boundaries. This milestone supplies persistence mechanics only. It does not decide whether a record is permitted, relevant, sensitive, or appropriate to present to a user.

# Functional Requirements

- Define typed MemoryRecord, MemoryType, MemoryStatus, MemorySource, and MemoryConsentLevel contracts.
- Provide an injectable MemoryRecordFactory for deterministic identifiers and timestamps.
- Define a provider-neutral MemoryStore contract with create, get, list, update, hard-delete, clear, and existence operations.
- Implement an InMemoryMemoryStore that retains records only for the current process.
- Reject duplicate identifiers rather than overwriting existing records.
- Replace a record's current value on update without retaining previous content.
- Hard-delete complete records without tombstones, audit entries, or recoverable references.
- Return records in ascending `memory_id` order.
- Return defensive copies so callers cannot mutate internal state.

# Deliverables

- Memory contract models.
- MemoryStore protocol and focused store exceptions.
- InMemoryMemoryStore reference provider.
- Unit tests for persistence mechanics, deterministic behavior, mutation safety, replacement, and hard deletion.

# Acceptance Criteria

- Records can be created, retrieved, listed, updated, deleted, cleared, and checked for existence.
- Duplicate creates raise a focused duplicate-memory error.
- Get, update, and delete operations for missing records raise a focused not-found error.
- Invalid records raise a focused invalid-operation error.
- Listing is deterministic by ascending `memory_id`.
- Records returned to callers cannot mutate stored state.
- Updates replace prior content, and hard deletion removes every backend-held reference.
- No external services, databases, files, policy decisions, retrieval ranking, or orchestration integration are used.

# Out of Scope

- MemoryWriter, MemoryRetriever, and MemoryPolicy implementations.
- Consent interaction or sensitive-data classification.
- Inferred memory, automatic expiry, semantic search, embeddings, and relevance ranking.
- Context Assembly integration.
- Persistent storage, encryption, multi-user ownership, audit logging, and project-document import.
- ConversationManager changes.

# Dependencies

- M2.1 Memory Contracts and Policy.
- ADR-003 Memory Architecture, Privacy, and Lifecycle.
