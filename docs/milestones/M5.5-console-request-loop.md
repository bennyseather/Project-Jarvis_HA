# Purpose

Provide a minimal interactive console loop for submitting user requests to the composed read-only Jarvis assistant.

# Decision

After read-only connectivity succeeds, the application accepts one line of user text at a time, passes it to `handle_request`, and displays the structured result. `quit` and `exit` end the loop cleanly.

The loop introduces no web server, voice interface, background automation, state-changing Home Assistant action, streaming, or persistence. It does not expose configuration tokens or raw provider errors. Provider failures are rendered as concise structured status messages.

# Acceptance Criteria

- A user can enter a conversational request and receive a response.
- A configured allow-listed entity state can be queried through the existing safe path.
- Empty input is ignored; `quit` and `exit` stop cleanly.
- Tests use an injected input/output boundary; no external service is contacted.

# Approval Decisions Required

1. Approve a console-only request loop as the first user interface.
2. Approve no voice, HTTP server, streaming, or background task in M5.5.
3. Approve concise structured error rendering without raw provider details.
