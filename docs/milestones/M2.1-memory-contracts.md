# Purpose

Define the provider-neutral contracts and privacy policy required before Jarvis can store or retrieve durable memory.

# Background

EPIC 2 adds durable assistant knowledge without duplicating Home Assistant state or making memory a dependency of every request. M2.1 establishes the approved taxonomy, record contract, lifecycle, consent rules, retention rules, and provider boundaries before any storage implementation exists.

# Functional Requirements

- Define MemoryRecord, MemoryType, MemoryStatus, MemorySource, MemoryConsentLevel, and retrieval-query contracts for future implementation.
- Support the initial taxonomy of preference, fact, instruction, project, episodic, and conversation-summary memory.
- Limit initial persistence eligibility to explicit, non-sensitive preference, fact, instruction, and project memory.
- Define traceable provenance using source, `source_request_id`, `memory_id`, and timestamps.
- Define policy-controlled explicit writing, sensitive-information confirmation, inspection, correction, and deletion behavior.
- Define provider-neutral MemoryStore, MemoryRetriever, MemoryWriter, and MemoryPolicy responsibilities.
- Define how Context Assembly may consume retrieved memory through ContextPackage without directly depending on a storage backend or ConversationManager.

# Deliverables

- Typed memory-contract models in a future implementation milestone.
- Provider-neutral memory interface definitions in a future implementation milestone.
- ADR-003 documenting taxonomy, policy, lifecycle, retrieval, and orchestration boundaries.
- Tests for contract validation and policy decisions in a future implementation milestone.

# Acceptance Criteria

- The record contract supports identity, provenance, consent, lifecycle, retention, correction, deletion, and extensibility.
- Initial policy allows only explicit, non-sensitive durable memory.
- Inferred persistence, automatic conversation summaries, episodic memory, temporary persistence, and automatic expiration are excluded from the initial release.
- Hard deletion prevents a deleted record from retrieval, search, restoration, and Context Assembly.
- Correction replaces the existing durable value without retaining prior content.
- Interface boundaries allow storage providers to be replaced without changing orchestration logic.

# Out of Scope

- Database, file, in-memory, or vector storage implementations.
- Embeddings, semantic search, or LLM memory extraction.
- Home Assistant history import.
- Automatic inferred-memory persistence.
- Event or audit infrastructure.
- Changes to existing orchestration behavior.

# Dependencies

- EPIC 1 orchestration foundation.
- ADR-002 Request Identity and Lifecycle.
- ADR-003 Memory Architecture, Privacy, and Lifecycle.
