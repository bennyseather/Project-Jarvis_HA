# Purpose

Assemble the bounded, relevant context that Jarvis needs to support a request and its selected orchestration path.

# Background

Context management is a core Jarvis responsibility. Context Assembly enriches the shared RequestContext with a typed ContextPackage while preserving Home Assistant's system-of-record role and the language model's reasoning role. It collects information but does not reason about, execute, or communicate that information.

# Functional Requirements

- Define a typed ContextPackage containing optional conversation, memory, Home Assistant, knowledge, time, and metadata sections.
- Define ContextProviders that return partial ContextPackages for a RequestContext.
- Collect registered provider output in deterministic registration order.
- Merge partial context packages and add the resulting package to RequestContext.
- Update RequestContext to CONTEXT_ASSEMBLED when assembly completes.
- Leave unavailable context sections empty.
- Keep providers independent: a provider must not invoke another provider.

# Deliverables

- A ContextPackage model.
- A ContextProvider protocol and ContextAssembler.
- Initial non-integrating placeholder providers.
- Tests for empty context and deterministic merging.

# Acceptance Criteria

- RequestContext.context_package is populated after assembly.
- All ContextPackage sections are optional.
- ContextAssembler queries every registered provider once in registration order.
- The same provider inputs always produce the same merged package.
- No provider executes capabilities, calls Home Assistant, retrieves memory, or contacts a language model.

# Out of Scope

- Memory retrieval or storage.
- Home Assistant integration.
- Capability execution.
- Prompt construction.
- Language-model interaction.
- Response generation.

# Dependencies

- M1.1 Request Classification.
- M1.2 Capability Registry.
- M1.3 Request Context.
