# M7.4 Home Assistant Acceptance Checklist

Configure dedicated safe test entities before running against a real home:

- `home_assistant.allowed_read_entities` includes one non-sensitive test entity.
- `home_assistant.action_policy.allowed_entities` includes one safe test light or switch.
- `confirm_required` includes only the matching allowed service, for example `light.turn_on`.
- No lock, alarm, cover, garage, script, automation, or administrative service is configured for this test.

Acceptance sequence:

1. Start Jarvis and confirm it discovers Home Assistant services without issuing a service call.
2. Query the configured read-only test entity and verify its current state matches Home Assistant.
3. Request an unconfigured entity and verify Jarvis rejects it without a Home Assistant read.
4. Request a configured action and verify Jarvis prints a summary and one-time confirmation token without executing.
5. Enter an invalid token and verify no Home Assistant action occurs.
6. Enter the exact valid token and verify only the configured safe entity changes state.
7. Reuse the token and verify no second action occurs.

Record the observed results without copying access tokens, raw provider payloads, or sensitive state into project files.

## Completed acceptance run

On 2026-07-25, the acceptance sequence ran against the explicitly configured
safe entity `light.blocks`.

- The configured entity state was read successfully.
- An unconfigured entity was denied before a Home Assistant read.
- The `light.turn_on` request produced a confirmation requirement without
  executing.
- An invalid confirmation token was denied.
- The exact valid token executed `light.turn_on` for `light.blocks` only.
- Reusing that token was denied.

The test light changed from off to on. No credentials, tokens, raw provider
payloads, or other entity state were recorded.
