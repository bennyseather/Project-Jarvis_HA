# Purpose

Implement provider-neutral, policy-controlled memory retrieval with deterministic baseline ranking.

# Background

Memory retrieval is separate from storage, writing, and context integration. MemoryStore provides records, MemoryPolicy decides lifecycle and privacy eligibility, query filters narrow eligible records, and MemoryRanker orders the remaining records. The retriever never writes memory or bypasses policy.

# Functional Requirements

- Define MemoryRetrievalQuery, MemoryMatch, MemoryRetrievalResult, and retrieval-policy result contracts.
- Support query text, request correlation, requested types, requested tags, maximum results, minimum importance, minimum confidence, evaluation time, metadata, and `include_sensitive`.
- Apply policy eligibility before all query filters and ranking.
- Exclude non-ACTIVE, expired, reserved-type, and policy-ineligible records.
- Exclude `SENSITIVE_CONFIRMED` records by default. `include_sensitive=True` requests consideration but does not override policy.
- Apply deterministic requested-type, match-any tag, minimum-importance, and minimum-confidence filters before ranking.
- Rank only remaining records and apply the maximum result limit after ranking.
- Return mutation-safe records and never modify MemoryStore.

## Query Filter Semantics

- An empty requested-type set allows all policy-eligible types.
- Requested tags use normalized, casefolded, whitespace-collapsed match-any behavior.
- A positive minimum importance or confidence excludes missing values; zero accepts missing values.
- `maximum_results` defaults to 10, must be non-negative, and returns no matches without invoking ranking when zero.
- Evaluation time comes from the query when supplied, otherwise from an injected clock.

## Baseline Ranking Semantics

Text and tags are Unicode-casefolded, trimmed, and internal whitespace is collapsed. Tokens are whitespace-delimited, unique token sets; no fuzzy matching, stemming, synonyms, embeddings, or language-model processing is used.

| Signal | Score |
| --- | --- |
| Exact normalized text match | +5.0 |
| Token overlap | Shared unique tokens divided by unique query tokens, multiplied by 4.0 |
| Requested-tag overlap | Matching requested tags divided by unique requested tags, multiplied by 2.0 |
| Importance | 0.0–1.0; missing contributes 0.5 |
| Confidence | 0.0–1.0; missing contributes 0.5 |
| Recency | 1.0 at age ≤ 0 days, linearly decays to 0.0 at 365 days using `updated_at` |

Exact and token-overlap scores may both apply. The total is the unrounded sum of the inspectable `exact_text`, `token_overlap`, `tag_overlap`, `importance`, `confidence`, and `recency` fields. Matches sort by total score descending, then `memory_id` ascending. Requested type is deliberately not a score because it is a hard filter.

# Deliverables

- Retrieval query, match, result, and eligibility contracts.
- MemoryPolicy retrieval-eligibility extension.
- MemoryRanker protocol and deterministic baseline ranker.
- MemoryRetriever protocol and policy-controlled implementation.
- Tests for policy eligibility, query filters, deterministic scores, ordering, mutation safety, and validation.

# Acceptance Criteria

- Policy-excluded records never reach ranking.
- Sensitive records are excluded by default and only considered with `include_sensitive=True` when policy approves.
- Non-active, expired, reserved-type, and query-filtered records are excluded.
- Score breakdowns expose every signal and sum to the total score.
- Ranking is deterministic with `memory_id` ascending as the final tie-breaker.
- Retrieval performs no writes, timestamp updates, external calls, embeddings, or semantic search.

# Out of Scope

- Context Assembly integration.
- Memory writing, correction, deletion, or automatic memory creation.
- Embeddings, vector databases, fuzzy libraries, semantic services, and LLM ranking.
- Natural-language sensitivity detection, audit logging, EventBus integration, multi-user ownership, Home Assistant, and ConversationManager changes.

# Dependencies

- M2.1 Memory Contracts and Policy.
- M2.2 In-Memory Store.
- M2.3 Explicit Memory Writing.
- ADR-003 Memory Architecture, Privacy, and Lifecycle.
