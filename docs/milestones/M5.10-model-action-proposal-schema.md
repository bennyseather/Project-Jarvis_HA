# Purpose

Allow the language-model adapter to produce a schema-validated generic Home Assistant action proposal that enters the existing capability gateway and confirmation flow.

# Decision

Extend the strict JSON proposal envelope with `home_assistant_action`:

```json
{
  "kind": "home_assistant_action",
  "message": "Optional user-facing explanation",
  "action": {
    "domain": "light",
    "service": "turn_on",
    "entity_ids": ["light.kitchen"],
    "service_data": {"brightness": 120},
    "summary": "Turn on the kitchen light"
  }
}
```

The adapter validates structural types only. It does not authorize services, entities, or fields; the composed Home Assistant capability gateway remains the authority for live-schema validation, risk policy, and confirmation.

Malformed action envelopes become unsupported and never reach the gateway. The model remains unable to call Home Assistant directly.

# Acceptance Criteria

- Valid generic action envelopes become typed action proposals.
- Missing or malformed domain, service, entity list, data, or summary becomes unsupported.
- The adapter passes no credentials and does not call Home Assistant.
- Existing conversation and read-only proposal behavior remains unchanged.
- Tests cover valid and malformed action envelopes.

# Approval Decisions Required

1. Approve strict JSON-only generic action proposals from the model.
2. Approve structural validation in the adapter and authorization/schema validation only in the capability gateway.
3. Approve rejection of every malformed action envelope before gateway handling.
