# Purpose

Establish a Capability Registry that records relevant, available Jarvis capabilities for the orchestration flow before any action is considered.

# Background

Jarvis coordinates assistance across its own context and Home Assistant's home domain. The Capability Registry gives later stages a reliable view of what Jarvis can offer for a classified request, while preserving Home Assistant as the owner of devices, entities, automations, integrations, and state. Capabilities describe what Jarvis can do; providers describe the integrations or plugins that make those capabilities available.

# Functional Requirements

- Maintain a catalog of capabilities and the providers that make them available.
- Identify capabilities relevant to a classified request.
- Describe each discovered capability in a form suitable for downstream selection.
- Indicate whether a capability is currently available for use.
- Exclude capabilities that are not relevant or cannot be used in the current request context.
- Provide a defined result when no relevant capability is available.
- Keep discovery separate from capability execution.
- Update RequestContext to CAPABILITIES_SELECTED when capability selection completes through the context-oriented interface.

# Deliverables

- A Capability Registry component or module.
- A documented capability description contract for downstream consumers.
- Tests for relevant capability selection, unavailable capabilities, and empty results.

# Acceptance Criteria

- A classified request can be evaluated for relevant capabilities.
- Discovery produces a consistent result for available, unavailable, and absent capabilities.
- The result enables a later stage to make an informed selection without performing an action.
- Discovery does not change Home Assistant state or invoke a capability.
- Tests demonstrate correct filtering and empty-result behavior.

# Out of Scope

- Request classification.
- Executing capabilities or Home Assistant services.
- Detailed context assembly.
- Language-model reasoning or final-response generation.
- Persistent memory and long-term learning.

# Dependencies

- M1.1 Request Classification.
