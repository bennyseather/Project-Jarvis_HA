# Purpose

Define the shared RequestContext object that flows through the Jarvis orchestration pipeline.

# Background

Jarvis components progressively enrich one request rather than creating unrelated models at each stage. RequestContext preserves the original request and carries classification, selected capabilities, assembled context, execution result, and a structured response between stages.

# Functional Requirements

- Preserve the original request throughout orchestration.
- Assign each RequestContext a unique request identifier and initial lifecycle state.
- Provide fields for request classification, selected capabilities, a context package, execution result, and a structured response.
- Allow each orchestration stage to populate its own field gradually.
- Remain a structured data object with no business logic.

# Deliverables

- A RequestContext model.
- Tests covering initial state and gradual enrichment.

# Acceptance Criteria

- The same RequestContext can be passed through every orchestration stage.
- All pipeline fields are optional until their responsible stage supplies them.
- New RequestContexts have a stable identifier and begin in the RECEIVED lifecycle state.
- The model contains no classification, provider, execution, or response behavior.

# Out of Scope

- Context assembly.
- Capability execution.
- Home Assistant integration.
- Memory retrieval.
- Language-model interaction.
- Response generation.

# Dependencies

- M1.1 Request Classification.
- M1.2 Capability Registry.
