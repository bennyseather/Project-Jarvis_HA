# Purpose

Allow the safe read-only assistant to resolve a user-friendly Home Assistant entity reference to one configured, allow-listed entity before querying its current state.

## Implementation Status

Approved and implemented. Resolution is deterministic, allow-list-only, and rejects ambiguous or unknown references before Home Assistant reads.

# Decision

M5.7 adds a provider-neutral `EntityReferenceResolver` used only after the language model proposes a read-only query. It receives the proposed reference and the configured allow-listed entity identifiers, then returns exactly one allowed entity, no match, or ambiguity. It never grants access to an entity outside the allow list.

Matching is deterministic and limited to exact normalized identifier, friendly-name, and configured alias matching. Multiple matches return a structured clarification-required result; they never select an arbitrary entity. The resolver reads no Home Assistant state and does not call services.

# Acceptance Criteria

- A known configured alias or friendly name resolves to one allow-listed entity.
- Unknown or non-allow-listed references are rejected.
- Ambiguous references require clarification and make no Home Assistant read.
- Existing exact entity-ID behavior remains supported.
- No state-changing capability, automatic learning, or entity authorization expansion is added.

# Approval Decisions Required

1. Approve resolver matching limited to configured aliases, entity identifiers, and friendly names.
2. Approve ambiguity returning clarification-required rather than selecting an entity.
3. Approve allow-list-first resolution with no authorization expansion.
